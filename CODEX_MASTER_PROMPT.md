# CODEX MASTER PROMPT — «КТО КАК ГОВОРИТ?»

Ты работаешь в уже подготовленном репозитории React + TypeScript + Vite. Твоя задача — довести его до надёжного MVP Telegram Mini App, а не переписывать продуктовую концепцию.

## 0. Сначала изучи проект
Прочитай `README.md`, `docs/PRODUCT_SPEC.md`, `docs/DESIGN_SPEC.md`, `docs/AUDIO_SPEC.md`, `docs/ANIMATION_SPEC.md`, `docs/TECH_SPEC.md`, `docs/RELEASE_CHECKLIST.md`, `telegram/bot-setup.md`, `data/animals.json` и текущие файлы `src/`. Проверь структуру и фактическое наличие медиа. Сначала выведи краткий план, затем реализуй без ожидания дополнительного подтверждения.

## 1. Продукт
«Кто как говорит?» — короткая совместная игра взрослого и ребёнка 18–24 месяцев. На главном экране 10 крупных карточек животных. Нажатие запускает короткую визуальную реакцию, затем реальный звук животного и русскую реплику диктора. Приложение не диагностирует речь и не оценивает ребёнка.

## 2. Строгие ограничения
- Не добавлять рекламу, аналитику, платежи, регистрацию, аккаунты, backend, рейтинги, баллы, таймеры, streaks, push-уведомления.
- Не использовать микрофон, запись голоса или распознавание речи.
- Не запускать звук автоматически при старте.
- Не генерировать фальшивые аудиофайлы и не подменять реальные голоса животных синтезом речи.
- Не заявлять, что черновые JPG имеют прозрачный фон или что отсутствующие аудио/анимации готовы.
- Не помещать Telegram bot token или другие секреты в клиентский код.
- Не отправлять `initData` и любые пользовательские данные куда-либо.
- Не добавлять функции вне MVP без отдельной необходимости.

## 3. Контент
Единый источник данных — `data/animals.json`, импортируемый через `src/data/animals.ts`; не дублируй данные в компонентах. Порядок: Корова, Кошка, Собака, Утка, Лошадь, Овечка, Свинка, Петушок, Лягушка, Лев. Не дублируй названия/пути в компонентах.

## 4. Главный UX
- Mobile-first, портретный экран, две колонки.
- На обычном телефоне показывай 10 карточек в пяти рядах, но не уменьшая touch target; на маленькой высоте разрешена прокрутка.
- Каждая карточка: крупное изображение, название, при выборе — звукоподражание.
- Большие зоны касания, скругления, светлая палитра из `docs/DESIGN_SPEC.md`.
- Не использовать декоративные элементы, мешающие нажатию.
- Учитывать `env(safe-area-inset-*)`, системные размеры и `prefers-reduced-motion`.
- Настройки: два независимых переключателя «Звуки животных» и «Голос диктора», пункт «О приложении».
- Сохранять только настройки в localStorage; корректно работать, если storage недоступен.

## 5. Аудиологика
- Использовать один контроллер.
- При новом нажатии немедленно остановить предыдущий файл и отменить предыдущую последовательность.
- Если включён звук животного — проиграть `animalAudio`; по завершении, если включён диктор, проиграть `voiceAudio`.
- Если один канал выключен — проиграть только другой.
- Если оба выключены — не создавать Audio.
- Не ставить звуки в очередь.
- Останавливать звук при `visibilitychange` в hidden и `pagehide`.
- Обрабатывать отсутствие файла, ошибку декодирования и rejection от `play()` без падения UI.
- Не показывать ложное сообщение «звук проигран», если файл отсутствует.
- Не начинать загрузку/воспроизведение до явного нажатия пользователя.

## 6. Медиа и временные ресурсы
В `public/assets/animals/` находятся временные JPG 1024×1024 с белым фоном. Используй их как черновые иллюстрации на светлых карточках. Подготовь простой способ заменить файл без изменения компонента. Не пытайся агрессивно вырезать белый фон автоматическим threshold, если это портит края персонажа.

Финальные аудиофайлы должны иметь пути:
- `public/assets/audio/animals/{id}.mp3`
- `public/assets/audio/voices/{id}.mp3`
Сейчас этих файлов может не быть. Добавь проверку наличия/ошибок и понятные комментарии в README. Не создавай заглушки с тишиной.

## 7. Telegram
- Приложение должно работать как обычный веб-сайт и как Telegram Mini App.
- Инициализируй WebApp SDK только если `window.Telegram?.WebApp` доступен.
- Вызови `ready()` после первого рендера; `expand()` использовать безопасно и не полагаться на него.
- Не требуй Telegram auth для MVP.
- Не отправляй `initData` на сервер.
- Учитывай ограничения WebView на аудио: воспроизведение только после жеста пользователя.

## 8. Качество кода
- TypeScript strict, не использовать `any` без необходимости.
- Компоненты небольшие и понятные.
- Данные отделены от UI.
- Нет лишних зависимостей.
- Клавиатурная доступность и корректные aria-label для кнопок/переключателей.
- Проверить ошибки изображений: при битом src показывать fallback с названием/иконкой, а не пустую карточку.
- Проверить узкие экраны от 320 CSS px и невысокие экраны.
- Не делать внешнюю загрузку шрифта обязательной: задать системный fallback.

## 9. Обязательные проверки
Выполни `npm install`, `npm run test`, `npm run build`. Добавь/исправь тесты для:
- выключены оба канала;
- включён только звук животного;
- включён только диктор;
- последовательность animal → voice;
- новое нажатие отменяет предыдущую последовательность;
- ошибка play() не ломает UI;
- настройки сохраняются и восстанавливаются.
Если не можешь запустить команды, честно укажи причину и не заявляй об успешной сборке.
